# CPU matching and certification

The optional Python 3.12 runtime is pinned in `requirements-matching.lock`. Install with `uv pip sync requirements-matching.lock --python .venv/bin/python` into a dedicated environment; the legacy application requirements are unchanged.

`training.train_models(examples, split)` compares rules, LogisticRegression and CatBoost on CPU (depth 6, 300 iterations, 2 threads, seed 42). It checks the frozen group/time split, fits text vocabulary on train only, fits sigmoid calibration on calibration only, and selects thresholds/champion on validation only. Unknown labels are excluded from binary fitting. Test examples never affect fitting or selection. The comparison does not certify accuracy. The separate model hash includes vocabulary, numeric feature schema, calibrator, selected threshold, runtime versions and native binary hash. `save_model` writes a new content-addressed directory; `load_model(trusted_root, hash)` rejects traversal, symlinks, modified content and runtime drift. No pickle is loaded.

`engine.run_match(item, policy, index, *, release, now, scorer=None, registry=None, mode="shadow", authority=None)` consumes an already pinned `SearchIndex`. `Release` wraps the existing `ReleaseManifest` with one `DecisionConfig` containing N, shortage treatment, ranking, dedupe, reuse and retrieval limits. It returns `EngineResult` with the existing `MatchDecision`, retrieval completeness, candidate constraints/probabilities/routes, requested count and shortage. The `MatchDecision` candidates are listing keys; current prices are in `candidate_checks[].candidate.price`.

Production requires `ReleaseAuthority` from an operator-owned protected root, matching activated release and evaluation hashes, a production source, active policy, fresh mandatory facts and complete retrieval. It reopens the public reader with `require_active=True` before processing, preserving its pin throughout the job. The source's `source_snapshot_verified=false` means external observation-window provenance; reconciled immutable local snapshots are accepted without inventing transactional external consistency. `OperatorContext` is constructed only by a trusted operator entrypoint; neither workbook reviewer cells nor ordinary run options may create it. Restrict filesystem write access to the authority root to operators. Authority activation is exposed as a programmatic operator action only; this implementation does not activate any production release.

`evaluate_candidate` requires that context and uses the same core. It bypasses only the prior-certificate check, emits `would_auto_confirm`/`would_auto_no_match`, and always leaves its business status as review-required. `MatchingStore.record_job` rejects evaluation results. A draft shadow rules release works without ML. Missing source fields remain UNKNOWN, including item-kind/latest-contract facts not supplied by the current producer.

`MatchingStore(path)` is a context-managed separate SQLite ledger with foreign keys, append-only triggers, single-writer transactions and idempotence keys covering canonical input, entire release/config, generation and snapshot. It copies full minimal candidate/request evidence for survival after snapshot retention. `import_review(review, operator, now=...)` checks copied evidence hash, role and validity, appends human resolution and returns a pending approval. It cannot mutate an old decision or current registry. Freeze a new `Registry` and candidate release for evaluation before activating reuse. Pair dependency keys exclude observation times and price amounts but retain specification, identifiers, units, parties, certificates, contract and exclusion dependencies. The current contract/freshness/price/search/ranking are always recomputed.

`evaluate_final(cases, release, runner, split=..., store=..., operator=..., registry=...)` consumes a frozen candidate exactly once in that ledger; supply `evaluate_candidate` as the runner. The test split is consumed before evaluation, so an interrupted attempt cannot silently tune and reuse it. Evaluate selected bundles, including every unresolved selection; no-match denominators include all declarations. Reports expose exact one-sided 95% Clopper–Pearson bounds, counts, coverage, retrieval recall/UNKNOWN/incompletion and missing holdouts. `releases.certify` only accepts eligible production evidence. Supplier and subsequent-time cases must be supplied as independently collected holdouts; flags do not establish their business provenance. A fixture, absent labels, zero positives, unresolved bundle, biased AL label, insufficient count or missing holdout cannot certify. 600 synthetic successes test the CI math only.

Validation commands: `python -m unittest test.test_matching_models test.test_matching_engine test.test_matching_store test.test_matching_reviews test.test_matching_evaluation -v`; real artifact flow: `python -m test.ml_surface_qa --out NEW_DIRECTORY`. The manual flow separately records the unmodified producer result (UNKNOWN/review) and explicitly annotated fixture-only facts, trains all three models, imports a review, advances source price 100→101, evaluates a frozen candidate registry and verifies production certification rejection. There are no reviewed business labels or actual quality/coverage claims. Large-catalog CPU benchmark and subsequent live-business holdouts remain rollout acceptance work.

## Split provenance and one-use study migration

Frozen split JSON now contains `seller_holdout` and exact `test_labels` payloads. `train_models` recomputes the same explicit group/time policy and compares the complete manifest, so a supported supplier holdout is accepted while changed assignments or provenance are rejected. Regenerate legacy split files with `freeze_split`; the public training and evaluation signatures are unchanged. The additive serialization contract is `core/matching/schemas/split.schema.json`.

`evaluate_final` requires exactly every frozen holdout request and label (no easy subsets or duplicate labels), checks their contents against the frozen payloads, stores that split, and reserves the entire declared test partition before invoking the runner. The test-content digest excludes train/calibration metadata. Append-only SQLite uniqueness additionally reserves request, revision, family, candidate and evidence identities plus canonical request contents, so changes to label text, release/model, dataset hash, or names of related request IDs do not reopen a consumed holdout. Overlapping claims roll back atomically; an interrupted runner leaves its claim consumed. Independent new request components can be evaluated normally.

The protected `MatchingStore` ledger is the operator study boundary. All releases and retraining attempts for that study must use the same persistent ledger; changing operator names does not reset it. Do not create another ledger to reuse old test. The schema adds `consumed_test_identities` without replacing existing data. A legacy ledger with consumed evaluations but no recoverable identity records rejects new evaluations; retain it as evidence and collect genuinely independent holdouts for a separately controlled study rather than resetting consumed history. Empty or fixture evaluation remains unmeasured/noncertifiable.
