# 초기 전체 수집 용량

2026-10-23 03:10 UTC에 실제 `shopping-all` API가 반환한 총수는 1,084,460건이다. 앞선 조회는 1,083,318건이었으며 검색 총수는 고정값이 아니다. 1·2,711·5,422·8,133·10,845페이지에서 460개 고유 품목을 표본으로 받았다. 이는 가격 오름차순의 다섯 위치 표본이며 무작위 표본이나 전체 실측은 아니다.

실제 품목을 별도의 fixture 저장소에서 현재 게시 형식으로 저장하고 엑셀을 생성했다. 측정용 저장소는 운영 데이터가 아니며 운영 정본으로 사용하지 않는다. 원본 페이지는 gzip 파일로 보존했다. 근거는 `.omo/collection-readiness/live-capacity/report.json` 및 같은 폴더의 원본 응답이다.

| 항목 | 표본 실측 / 전체 추정 |
|---|---|
| 표본 SQLite 게시본 | 460건, 6,520,832바이트 |
| 초기 SQLite 게시본 | 약 15.37GB |
| 수집 중간 저장 | 약 19.35GB, 원본 페이지 gzip 포함 |
| 초기 엑셀 | 약 356.7MB |
| 게시본 3개와 중간 저장, 20% 여유 | 약 78.6GB 여유 공간 권장 |
| 압축 전 누적 응답 | 약 81.3GB; HTTP 전송량의 실측값은 아님 |

GB는 10억 바이트 기준이다. 원본 응답에는 품목 외의 업체·검색 필터 목록이 반복되어 들어간다. 표본 페이지는 약 7.2~7.6MB였고 gzip 저장 시 약 1.0~1.1MB였다. 이미지는 URL만 저장하며 이미지 파일 자체는 다운로드하지 않는다. Prefect/PostgreSQL, Docker 이미지, 로그, 별도 백업 및 향후 가격·상품 변경 이력의 누적은 표의 추정에서 제외했다.

표본 요청은 약 9.9~23.4초였다. 이를 네 작업에 단순 배분한 네트워크 시간 추정은 약 10.3시간이며 SQLite 처리·게시·재시도·동시 접속 시 속도 변화는 반영하지 않았다. 실제 완료 시간은 보장하지 않는다. 관측 구간 12시간 제한, 건수 변동 및 누락·반복 검사에 실패하면 운영 게시본을 만들지 않는다.

로컬 호스트 여유 공간은 측정 시 약 109GiB였다. Docker 내부 파일시스템은 약 958GB 여유로 표시했으나 이것은 호스트 물리 여유 공간과 다르다. 호스트 디스크도 확인해야 한다. 계속 갱신할 경우 이력이 누적되므로 초기 용량만으로 장기 운영 용량을 판단하지 않는다.

측정 재실행은 저장소 루트에서 전체 테스트 의존성이 설치된 Python 환경으로 실행한다. 출력 디렉터리는 새 경로를 지정해야 한다.

```sh
python -m test.updater_capacity --out-dir /path/to/new-capacity-measurement
```
